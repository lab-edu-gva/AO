# Sesión 09 – Diagnóstico y resolución de incidencias de instalación y uso

> **Material de estudio del alumnado.** Esta sesión está preparada para su estudio y trabajo; su estado no implica que ya se haya impartido.

## 1. Objetivos de aprendizaje
Al finalizar esta sesión deberías ser capaz de explicar los conceptos desarrollados, aplicar el procedimiento guiado y resolver las actividades propuestas justificando tus decisiones.

## 2. Relación curricular
- **Unidad:** Instalación de Aplicaciones y Entornos de Trabajo Colaborativo.

## 3. Contenidos y explicación teórica
# 1. Qué es una incidencia
Una **incidencia** es un problema que interrumpe, degrada o impide el funcionamiento esperado de un equipo o aplicación. Puede aparecer durante la descarga, instalación, configuración, actualización o utilización. El objetivo del soporte no es probar soluciones al azar, sino recopilar evidencias, identificar la causa probable, aplicar una actuación segura y verificar el resultado.

# 2. Síntomas, causas y evidencias
El síntoma es lo que observa el usuario: “la aplicación se cierra”. La causa es el motivo que lo provoca: falta de memoria, archivo dañado, incompatibilidad, permiso insuficiente o conflicto con otro componente. No deben confundirse. Una misma causa puede producir varios síntomas y un mismo síntoma puede tener causas diferentes.

Las evidencias incluyen mensaje exacto, código de error, momento en que aparece, acciones previas, versión, sistema operativo, cambios recientes y alcance del problema. Las capturas deben evitar mostrar contraseñas o datos personales.

# 3. Método sistemático de diagnóstico
1. **Escuchar y delimitar:** qué ocurre, desde cuándo y a quién afecta.
2. **Reproducir:** comprobar si el fallo puede repetirse sin poner en riesgo los datos.
3. **Recopilar datos:** mensajes, versiones, registros y cambios recientes.
4. **Formular hipótesis:** enumerar causas plausibles.
5. **Priorizar:** empezar por comprobaciones sencillas, seguras y reversibles.
6. **Aplicar una solución:** realizar un cambio cada vez para identificar su efecto.
7. **Verificar:** repetir la operación que fallaba y comprobar efectos secundarios.
8. **Documentar y cerrar:** registrar causa, solución y recomendaciones.

# 4. Incidencias frecuentes
- Instalador incompatible con el sistema o arquitectura.
- Espacio insuficiente en disco.
- Falta de permisos.
- Descarga incompleta o archivo corrupto.
- Dependencia ausente.
- Antivirus o política corporativa que bloquea una operación legítima.
- Configuración incorrecta o perfil dañado.
- Actualización interrumpida.

# 5. Qué no debe hacerse
No desactivar protecciones de seguridad sin autorización, no ejecutar archivos desconocidos como administrador, no borrar carpetas del sistema, no instalar DLL de páginas no fiables, no compartir contraseñas y no repetir cambios destructivos sin copia. Si el problema supera las competencias o permisos del técnico, se escala al soporte responsable con evidencias suficientes.

## 4. Ejemplo práctico guiado
## Ejemplo guiado: “La aplicación no se abre”
1. Pregunta si aparece un mensaje y solicita el texto exacto.
2. Comprueba si afecta a un usuario o a todos.
3. Averigua si empezó después de una actualización.
4. Comprueba versión, espacio disponible y estado del sistema.
5. Revisa si el proceso queda abierto o se cierra inmediatamente.
6. Consulta la ayuda oficial y registros disponibles.
7. Aplica una prueba segura, por ejemplo reiniciar la aplicación o comprobar una configuración documentada.
8. Repite la operación y registra el resultado.

No reinstales inmediatamente: podrías perder configuración y ocultar la causa original.

## 7. Material del alumnado: actividades
## Actividad 1. Árbol de diagnóstico
Diseña un árbol de decisión para la incidencia “no puedo instalar la aplicación”. Incluye al menos cinco comprobaciones y sus posibles resultados.

## Actividad 2. Síntoma o causa
Clasifica: “aparece error 1603”, “no hay espacio”, “el instalador se cierra”, “falta permiso de administrador”, “la aplicación no inicia”. Indica qué datos faltan para diagnosticar cada caso.

## Actividad 3. Caso práctico
Un usuario indica que después de actualizar la aplicación no puede abrir archivos antiguos. Describe preguntas, evidencias, hipótesis, comprobaciones y criterios para escalar el caso.

## 8. Preguntas de repaso y preparación del examen
- ¿Qué diferencia hay entre síntoma y causa?
- ¿Qué información debe recopilarse antes de actuar?
- ¿Por qué conviene cambiar una sola variable cada vez?
- ¿Qué significa que una solución sea reversible?
- ¿Cuándo debe escalarse una incidencia?

## 9. Resumen de estudio
En esta sesión se han trabajado los conceptos y procedimientos necesarios para comprender **diagnóstico y resolución de incidencias de instalación y uso**. Para preparar el examen, debes poder definir los términos principales, explicar por qué se realiza cada paso, identificar riesgos y justificar una actuación técnica adecuada. No memorices únicamente listas: relaciona cada decisión con el problema que evita o resuelve.
