# Sesión 07 – Actualización y mantenimiento de aplicaciones

## 3. Contenidos y explicación teórica
# 1. Por qué se actualiza el software
Una actualización modifica una aplicación instalada para corregir errores, cerrar vulnerabilidades, mejorar estabilidad, añadir funciones o mantener compatibilidad. Mantener el software actualizado reduce riesgos, pero actualizar sin planificar también puede provocar incompatibilidades. Por eso las actualizaciones deben gestionarse, no aceptarse a ciegas.

# 2. Tipos de actualización
- **Parche de seguridad:** corrige una vulnerabilidad.
- **Corrección de errores:** resuelve fallos conocidos.
- **Actualización funcional:** incorpora o modifica características.
- **Actualización mayor:** puede cambiar versión principal, interfaz o requisitos.
- **Actualización menor:** introduce mejoras o correcciones dentro de una misma rama.

La nomenclatura de versiones varía entre fabricantes. No se debe interpretar un número de versión sin consultar el esquema utilizado por el producto.

# 3. Ciclo de mantenimiento
1. Identificar aplicaciones instaladas y versiones.
2. Consultar avisos y versiones disponibles en fuentes oficiales.
3. Evaluar urgencia, impacto y compatibilidad.
4. Realizar copia o definir recuperación cuando el riesgo lo aconseje.
5. Probar en un equipo de referencia si el entorno es crítico.
6. Programar y ejecutar la actualización.
7. Verificar inicio, funciones principales y compatibilidad.
8. Documentar versión anterior, nueva y resultado.

# 4. Actualizaciones automáticas y manuales
Las automáticas reducen el tiempo durante el que el equipo permanece vulnerable y facilitan el mantenimiento. Las manuales permiten controlar el momento y validar cambios, pero requieren seguimiento. En organizaciones se pueden utilizar políticas centralizadas para desplegar actualizaciones de forma escalonada.

# 5. Riesgos y reversión
Una actualización puede cambiar formatos, complementos, requisitos o comportamiento. Antes de una actualización importante conviene revisar notas de versión, compatibilidad y opciones de recuperación. Si falla, no se debe descargar una versión antigua de cualquier sitio: se utiliza el repositorio oficial y el procedimiento autorizado.

## 4. Ejemplo práctico guiado
## Ejemplo guiado: comprobar una actualización
1. Abre la opción “Acerca de” o “Buscar actualizaciones”.
2. Identifica la versión instalada.
3. Consulta el canal oficial del fabricante para conocer la versión estable y sus notas.
4. Comprueba si la actualización es compatible con el sistema y los complementos utilizados.
5. Sigue el método de actualización recomendado.
6. Reinicia si se solicita.
7. Vuelve a consultar la versión y prueba las funciones esenciales.
8. Registra el resultado.

En un equipo de aula, no interrumpas una actualización en curso ni apagues el equipo salvo que el procedimiento oficial lo indique.

## 7. Material del alumnado: actividades
## Actividad 1. Clasificación
Clasifica cinco ejemplos de cambios como parche de seguridad, corrección, actualización funcional o actualización mayor. Explica qué información necesitarías para clasificarlos.

## Actividad 2. Plan de actualización
Diseña un plan para actualizar una aplicación instalada en 25 equipos de un aula. Incluye inventario, prueba piloto, calendario, comunicación, verificación y registro.

## Actividad 3. Decisión
Una actualización importante aparece el día anterior a una actividad evaluable. Explica qué factores valorarías antes de aplicarla a todos los equipos.
